## M-A-GOOGLE-CHAT-ANSWER-IS-ONE-MESSAGE-1 — a streamed answer on Google Chat arrives as one message, not one per sentence group

**Why:** found 2026-09-30 building `M-GOOGLE-CHAT-POSTS-AT-GOOGLES-PACE-1`: the reply buffer sends each
sentence-ended chunk of 200+ characters as its own message, so a 2,000-character answer is about eight Chat
messages, and at Google's one write a second it takes about eight seconds. Discord shows a typing line and
reads the same stream well; Google Chat shows eight notifications.

**Tasks:**
- [ ] On Google Chat, the parts of one answer queued while a write waits are merged into one message, up to Google's message size
- [ ] Test: unit — a 2,000-character streamed answer is one or two Chat messages, and Discord's chunking is unchanged

**Done when:** an answer on Google Chat reads as one message.

## Out of scope for v0.1 (deferred)

- **Slack / Telegram adapters** — Tier-0 only, by customer request.
- **Multi-bot per agent** — one bot per template is the PoC contract.
- **Persistent session-store across container redeploys** — v0.1
  relies on mem0 + the persisted workspace inside the agent container
  to recover continuity on the next user turn. A dedicated
  session-store (à la OpenACP) is a v0.2 concern.
- **Skill command pinning, slash commands, button-based permission
  approval** — explicit UX-incompatibility per cerase M2 rules.
- **Doctor checks** — deferred; structured pino logs cover the PoC
  observability need.
