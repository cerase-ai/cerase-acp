## 🔄 M-GOOGLE-CHAT-PLACEHOLDER-TURNS-INTO-AN-ELLIPSIS-1 — the «Sto scrivendo…» line is edited, not deleted

**Why:** the operator, 2026-09-29: a Chat line that disappears when the answer arrives reads badly. An app may
edit what it wrote (`spaces.messages.patch`), and an edit rings no phone, so the answer stays a message of its own.

**Tasks:**
- [~] When the first part of the answer is sent, the placeholder's text becomes «…» instead of the message being deleted; the answer stays a new message
- [ ] A turn that ends with nothing to say, fails or times out leaves the placeholder as «…» too
- [ ] Test: unit — every path of the existing placeholder tests ends with one edit to «…» and no delete

**Done when:** on Google Chat the placeholder turns into «…» above the answer, and nothing is deleted.

## Out of scope for v0.1 (deferred)

- **Slack / Telegram adapters** — Tier-0 only, by customer request.
- **Multi-bot per agent** — one bot per template is the PoC contract.
- **Persistent session-store across container redeploys** — v0.1
  relies on mem0 + the persisted workspace inside the agent container
  to recover continuity on the next user turn. A dedicated
  session-store (à la OpenACP) is a v0.2 concern.
- **Skill command pinning, slash commands, button-based permission
  approval** — explicit UX-incompatibility per cerase M2 rules.
- **Doctor checks** — deferred; structured pino logs cover the PoC
  observability need.
