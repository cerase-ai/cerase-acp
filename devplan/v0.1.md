## ✅ M-GOOGLE-CHAT-POSTS-AT-GOOGLES-PACE-1 — a long answer on Google Chat stays inside the per-space write limit

**Why:** found 2026-09-30 building the 💬 placeholder: Google Chat allows 1 write a second per space, shared by
create, patch and delete (developers.google.com/workspace/chat/limits), and answers 429 over it. The shared send
queue spaces messages 100 ms apart, a pace set for Discord, so an answer sent as several Chat messages can exceed
it, with or without the placeholder.

**Tasks:**
- [x] Chat posts and edits in one space are paced at no more than one a second, Discord keeps its own pace
- [x] A 429 is retried with backoff instead of losing the part of the answer it refused
- [x] Test: unit, on fake timers — a five-part answer plus the placeholder edit never makes two writes in one second, and a 429 is retried

**Done when:** an answer of any length arrives whole on Google Chat.

## 🔄 M-GOOGLE-CHAT-PLACEHOLDER-IS-SEEN-LIVE-1 — the 💬 placeholder checked on a real Chat conversation

**Why:** `M-GOOGLE-CHAT-SHOWS-THE-ASSISTANT-IS-WRITING-1`, `M-GOOGLE-CHAT-PLACEHOLDER-TURNS-INTO-AN-ELLIPSIS-1` and
`M-GOOGLE-CHAT-PLACEHOLDER-IS-A-SPEECH-BALLOON-1` were archived on unit tests against a fake Google. Release

`cerase-acp:sha-443a289` or later, the image built from code `b67e000`. An injected turn does not pass through the adapter's inbound path, so only a
message typed on Google Chat shows the line.

**Tasks:**
- [ ] 👤 in place — the operator writes to an assistant on Google Chat on `lt-seats-2`: Google accepts events only from its own servers, so nothing here can send one
- [ ] A 💬 appears within a second, becomes «…» above the answer, the answer rings the phone, and the bridge log shows one post and one edit for the turn

**Done when:** on a real Chat conversation a 💬 turns into «…» above an answer that notifies.

## Out of scope for v0.1 (deferred)

- **Slack / Telegram adapters** — Tier-0 only, by customer request.
- **Multi-bot per agent** — one bot per template is the PoC contract.
- **Persistent session-store across container redeploys** — v0.1
  relies on mem0 + the persisted workspace inside the agent container
  to recover continuity on the next user turn. A dedicated
  session-store (à la OpenACP) is a v0.2 concern.
- **Skill command pinning, slash commands, button-based permission
  approval** — explicit UX-incompatibility per cerase M2 rules.
- **Doctor checks** — deferred; structured pino logs cover the PoC
  observability need.
